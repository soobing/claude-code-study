# 병렬 오케스트레이션 실습 (Parallel Orchestration Practice)

Claude Code가 작업을 병렬화하는 **네 가지 방식**을, 하나의 샘플 코드베이스(`mini-blog/`) 위에서
직접 돌려보며 **차이를 몸으로 느끼는** 실습입니다.

네 방식의 본질적 차이는 "무엇을 하느냐"가 아니라 **작업자와 나의 관계(토폴로지)** 입니다.

| 방식 | 조율 주체 | 작업자끼리 소통 | 결과 회수 | 개별 개입 |
| ---- | -------- | -------------- | -------- | -------- |
| 서브에이전트     | 나 (직접 지시) | ✗           | 자동 반환      | ✗ (블랙박스) |
| 에이전트 뷰      | 나 (관제판)   | ✗           | 찾아가서 확인   | ✓ (들어감)   |
| 에이전트 팀      | **리더 Claude** | **✓ (메시징)** | 리더가 종합   | ✓ (팀원 세션) |
| 동적 워크플로우  | **스크립트**     | ✗ (검증만)     | 종합 하나 반환 | ✗ (블랙박스) |

> 한 방향으로 읽으면: 조율 주체가 `나 → 나 → Claude 리더 → 스크립트`로 옮겨가고,
> 작업자끼리의 관계가 `없음 → 없음 → 수평 소통 → 수직 검증 파이프라인`으로 진해집니다.

---

## 샘플 코드베이스: `mini-blog/`

의존성 없는 초소형 블로그 API (Node 내장 http만 사용). **일부러 흠집을 심어**두었습니다.

```
mini-blog/
├── src/
│   ├── posts.js    # CRUD 로직   (검증 누락, 소유자 확인 없음, 페이지네이션 버그)
│   ├── auth.js     # 토큰 검증   (빈 토큰 통과, 만료 미검사)
│   ├── db.js       # 인메모리 저장소 (삭제 후 id 재사용 함정, update가 필드 통째 교체)
│   └── server.js   # 라우팅      (DELETE가 인증을 우회)
├── tests/          # 거의 비어 있음 → 채우는 게 연습거리
├── package.json
└── README.md       # 실제 코드와 어긋남 → 갱신이 연습거리
```

심어둔 흠집(스포일러)은 이 파일 맨 아래 <details>에 접어두었습니다. 먼저 각 방식으로 찾아보세요.

## 연습 1 — 서브에이전트 (자식 / 일방향 보고)

**목표**: 위임한 부작업이 요약으로만 돌아오고, 내 대화가 오염되지 않는 경험.

> **과제**: "`auth.js`의 토큰 검증이 프로젝트 전체 어디서 호출되는지, 그리고 검증을
> 우회할 수 있는 경로가 있는지 찾아줘."

- **실행**: Claude에게 위 문장을 그대로 요청 → Claude가 `Explore` 서브에이전트를 띄웁니다.
- **관찰 포인트**:
  - grep 결과·파일 덤프가 우리 대화에 쌓이지 않고 **요약만** 돌아온다.
  - 서브에이전트에 "들어가서 대화"하는 개념이 **없다**.
- **관계**: 부모 → 자식, 결과 자동 반환, 블랙박스.

## 연습 2 — 에이전트 뷰 (독립 세션 / 내가 관제)

**목표**: 서로 무관한 세션 여러 개를 던져놓고, 관제판에서 골라 개입하는 경험.

> **과제**: 서로 무관한 작업 3개를 **동시에** 디스패치
> 1. `README.md`를 실제 코드에 맞게 갱신
> 2. `tests/`에 posts CRUD 테스트 추가
> 3. `db.js` 리팩터링 (id 재사용 함정 수정)

- **실행**: 터미널에서 `claude agents`로 뷰를 열고 세션 3개를 디스패치 →
  상태판을 보다가 하나에 **들어가(attach)** 개입.
- **관찰 포인트**:
  - 세 세션은 서로를 **모른 채** 독립적으로 돈다.
  - 결과가 내 컨텍스트로 자동으로 안 들어온다 → 내가 **찾아가서** 확인.
- **관계**: 동료 세션들 + 내 관제판.

## 연습 3 — 에이전트 팀 (리더가 배분 / 수평 소통)

**목표**: 큰 목표 하나만 던지면 리더 Claude가 쪼개고 배분·동기화하는 경험.
(에이전트 팀은 실험적 기능이며 기본 비활성화 — 먼저 활성화 필요)

> **과제**: "댓글(comments) 기능을 처음부터 끝까지 추가해줘 —
> 모델, API 라우트, 테스트, README 반영까지."

- **실행**: 팀 기능을 켠 뒤 위 목표 하나만 전달.
- **관찰 포인트**:
  - **리더 Claude**가 "모델 담당 / 라우트 담당 / 테스트 담당"으로 쪼개
    **공유 작업 목록**에 올린다.
  - 세션끼리 **메시지로 동기화**한다 (앞 두 방식엔 없던 수평 소통).
- **관계**: 나 → 리더 → 팀원, 팀원끼리도 옆으로 소통.

## 연습 4 — 동적 워크플로우 (스크립트 지휘 / 교차 검증)

**목표**: 스크립트가 다수 작업자를 팬아웃하고, 결과를 서로 **반박 검증**한 뒤 종합.

> **과제**: "전 파일을 감사해서 버그를 찾되, 각 발견을 다른 에이전트가 **반박 검증**하고,
> 살아남은 것만 종합해줘."

- **실행**: `Workflow`로 `find → adversarial verify → synthesize` 파이프라인을 실행.
  (스크립트는 Claude에게 짜달라고 하면 됩니다.)
- **관찰 포인트**:
  - 작업자끼리 **대화는 안 하고**, 스크립트가 A의 발견을 B에게 넘겨 **검증만** 시킨다.
  - 끝나면 **종합 결과 하나**가 반환된다. 개별 작업자에 들어갈 수 없다(블랙박스).
- **관계**: 나 → 스크립트 → (팬아웃) 다수 작업자 → 서로 검증 → 종합 → 반환.

---

## 연습을 관통하는 한 가지 원리

각 연습은 **바로 앞 연습에 딱 한 가지 능력**만 더합니다. 그 "한 가지"가 그 방식의 정체성입니다.

| 연습 | 새로 등장하는 능력 | "아, 이래서 다르구나" |
| ---- | ----------------- | -------------------- |
| 1 서브에이전트   | 위임 + 요약 반환   | 개입 불가, 자동 회수    |
| 2 에이전트 뷰    | 독립 지속 + 개입   | **들어갈 수 있다**       |
| 3 에이전트 팀    | 리더 + 수평 소통   | **작업자끼리 대화한다**   |
| 4 워크플로우     | 스크립트 + 교차검증 | **결과를 서로 검증한다**  |

<details>
<summary>심어둔 흠집 목록 (스포일러 — 먼저 직접 찾아본 뒤 펼치세요)</summary>

- **auth.js**: `verifyToken`이 빈 토큰(`!token`)을 `valid:true`로 통과시킴 / 만료(`expiry`)를
  파싱만 하고 비교하지 않음 / 서명 검증이 전혀 없음.
- **posts.js**: `createPost`가 title·body 검증 없이 저장 / `updatePost`가 소유자 확인 없이
  누구나 수정 가능 / `listPosts`의 `start = page * size`는 1-based page에서 첫 페이지를 건너뜀
  (off-by-one).
- **db.js**: `insert`의 `nextId = posts.length + 1`은 삭제가 일어나면 **id가 중복** 발생 /
  `update`가 `{ id, ...patch }`로 기존 필드(title 등)를 통째로 날림 / `==` 느슨한 비교.
- **server.js**: `DELETE /posts/:id`가 `verifyToken`을 거치지 않고 바로 삭제 (인증 우회 경로).

</details>
